========================================
我的世界基岩版玩家数据移动工具 · 使用说明
========================================

【它能干什么】
把存档 db 里的玩家数据（背包、末影箱、坐标、等级、药水效果…）原样搬到另一个存档。
不修改存档的方块、实体、村庄等任何其它内容。

【三个脚本】
  merge_players.py      搬服务器玩家数据  player_server_<uuid>
  move_local_player.py  搬本地玩家数据    ~local_player
  ldb_tool.py           查看/复制任意键（排查用）

----------------------------------------
一、准备环境（只需做一次）
----------------------------------------
1) 安装 Python 3.12
   注意：必须是 3.12。3.13 / 3.14 装依赖会因缺少预编译包而失败。

2) 安装依赖（在本文件夹打开命令行）
   pip install -r requirements.txt

   如果 pip 很慢，可以换镜像：
   pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

----------------------------------------
二、操作前必做
----------------------------------------
1) 完全关闭游戏 / 服务器（不是最小化，是进程退出）。
   LevelDB 目录里有 LOCK 文件，运行中写入会损坏存档。

2) 备份整个世界文件夹（至少把 db 复制一份改名 db.bak）。

3) 确认要搬的是哪一种：
   服务器存档 → 键名 player_server_<uuid>  → 用 merge_players.py
   单人存档   → 键名 ~local_player        → 用 move_local_player.py

----------------------------------------
三、搬服务器玩家数据（最常用）
----------------------------------------
第 1 步：空跑，只列清单不写入

   python merge_players.py "旧存档\db" "新存档\db" --dry-run

   看输出第一行：
     [i] 旧库：player_server_* 19 条 ...
   如果显示 0 条，说明参数顺序反了，或者这个库根本没有服务器玩家数据。

第 2 步：真写

   python merge_players.py "旧存档\db" "新存档\db"

   脚本会自动：
     - 把新库里会被覆盖的旧值备份到 新存档\db\.player-backup\<时间戳>\
     - 写完回读，逐字节校验，打印「校验通过」

第 3 步：开服，让其中一位玩家进服，检查背包 / 坐标 / 等级。

参数顺序永远是：旧库 → 新库。

----------------------------------------
四、搬本地玩家数据（单人存档）
----------------------------------------
   python move_local_player.py show "存档\db"
   python move_local_player.py copy "旧存档\db" "新存档\db" --dry-run
   python move_local_player.py copy "旧存档\db" "新存档\db"

注意：服务器记录（player_server_*）和本地记录（~local_player）结构不同，
不能互相直接搬。服务器 → 服务器、本地 → 本地，才可以按字节复制。

----------------------------------------
五、出问题怎么查
----------------------------------------
1) 看这个库里到底有什么键：
   python ldb_tool.py list "存档\db" player_server_

2) 看某条记录多大：
   python ldb_tool.py size "存档\db" ~local_player

3) 看开头字节（确认不是空的）：
   python ldb_tool.py hex "存档\db" ~local_player 32

4) 报 LOCK / IO error：
   游戏或服务器还在跑，或者上次没退干净。关掉后重试。

5) 报 ModuleNotFoundError: leveldb：
   依赖没装，或者用错 Python 版本（必须是 3.12）。

6) 进游戏发现数据没变：
   先确认服务器确实读的是你改的那个 db 目录（有的面板服会另存一份）。

----------------------------------------
六、还原
----------------------------------------
- merge_players.py：到 新存档\db\.player-backup\<时间戳>\ 里找 <键名>.bin，
  用 ldb_tool.py put 写回去。
- move_local_player.py：到 新存档\db\.local-backup\<时间戳>\local_player.bin，
  同样用 put 写回 ~local_player。
- 最稳的还是直接用事先复制的 db.bak 整个覆盖回去。

----------------------------------------
七、原理（一句话）
----------------------------------------
存档是 LevelDB 数据库，玩家数据就是里面几个键值对；
用打过 Mojang zlib 补丁的绑定（amulet-leveldb）打开，get 出来、put 进去即可。
.ldb 文件本身不能用十六进制编辑器改——它有 CRC 校验，改一个字节整库就废。
