## 1. 这个程序是什么

把原来分散的几样东西合成了一个窗口：

| 原来 | 现在 |
|---|---|
| `main.exe` + `app.html` | 「任务」分区（每日/每周/每月） |
| `data_editor.py` + `editor.html` | 「数据」分区（查看、补卡、单日明细） |
| `add_app_data.py` | 「工具」→ 补全缺失周期 |
| `sort_app_data.py` | 「工具」→ 排序与一致性校验 |
| `report_viewer/` | 「报告」分区 |
| —— | 「总览」分区（今日进度 + 补卡名额 + 考试节点） |

运行方式：本地起一个只监听 `127.0.0.1` 的 HTTP 服务，再用 Edge 的
`--app` 模式打开，所以看起来是一个独立窗口，没有地址栏和标签页。

不依赖 .NET / pythonnet，单文件 exe 约 8.8 MB。

## 3. 启动流程

1. `CycleQuest.exe` 启动，`server.py` 找到可用端口（47321–47340）。
2. 起 HTTP 服务，`/` 返回 `shell.html`。
3. 用 Edge 打开 `http://127.0.0.1:端口/`，窗口 560×860。
4. 页面每 20 秒发一次心跳；窗口关掉后 5 分钟没请求，服务自动退出。
5. 数据读写全部走 `Store`：写前备份、临时文件 + 原子替换。

调试时可以设环境变量：

```
CYCLEQUEST_NO_WINDOW=1   只起服务，不开窗口
CYCLEQUEST_DATA=路径      指定数据文件（备份/日志也跟着走）
```

## 4. 数据格式

`app_data.json` 是「key → JSON 字符串」：

```json
{
  "quest_daily_v4_2026-11-24": "{\"period\":\"2026-11-24\",\"quests\":[{\"id\":\"d1\",\"text\":\"四级 25 分钟\",\"done\":false}]}",
  "quest_weekly_v4_2026-11_W4": "{\"period\":\"2026-11_W4\",\"quests\":[...]}",
  "quest_monthly_v4_2026-11": "{\"period\":\"2026-11\",\"quests\":[...]}"
}
```

- 每日：`quest_daily_v4_YYYY-MM-DD`
- 每周：`quest_weekly_v4_YYYY-MM_Wn`
- 每月：`quest_monthly_v4_YYYY-MM`
- value 必须是字符串，里面再套一层 JSON；任务字段：`id`、`text`、`done`，可选 `meta`。

`makeup_log.json`：

```json
{"2026-11-24": 1}
```

只记「这一天用掉了几个补卡名额」，不记录补了哪条任务。

## 5. 补卡规则（重要，别改错）

这是按使用者要求定下的，写在 `server.py`：

| 规则 | 实现位置 |
|---|---|
| 周一到周五 2 个/天，周六周日 3 个/天 | `weekday_limit()` |
| 名额当天有效，不累积 | `makeup_used()` + `makeup_log.json` |
| 只能补今天之前 | `eligible_day()` 里 `period >= today` 跳过 |
| 只能补最近一个还有未完成的日期 | `eligible_day()` 从新到旧找第一个未完成 |
| 必须补完这一天才能继续往前 | 同上，最近未完成日之前的不允许 |
| 补完直接 `done=true`，不记 makeup 字段 | `_makeup()` 只改 `done` |
| 不能撤销 | 没有撤销接口；UI 也没有 |
| 名额由服务端校验 | `_makeup()` 里重新读文件、重新算名额 |

> 注意：因为不记 makeup 字段，完成率/报告会把补卡算成正常完成。
> 这是使用者明确选择的，不是 bug。

## 6. 接口一览

| 方法 | 路径 | 用途 |
|---|---|---|

## 8. 重新打包

环境：Python 3.13 + PyInstaller（当前 6.22.2）。不需要 pywebview。

在 `任务系统2.0\源码` 里双击 `build.bat`，或手动：

```bat
pyinstaller --noconfirm --clean --onefile --windowed --name CycleQuest ^
  --add-data "shell.html;." ^
  --add-data "app.html;." ^
  --add-data "report;report" ^
  server.py
```

产物在 `源码\dist\CycleQuest.exe`，复制回 `任务系统2.0\` 覆盖旧 exe。
**不要覆盖 `app_data.json`。**

打包注意：

- `--windowed` 后没有控制台，`server.py` 已把 stdout/stderr 重定向到 `cyclequest.log`。
- `report` 目录必须用 `--add-data` 带进去，否则报告页 500。
- onefile 启动要解压，第一次会慢几秒，正常。
- 如果换 Python 版本，先确认 `server.py` 能直接 `python server.py` 跑起来。

## 9. 测试清单

改完至少过一遍：

1. 双击 exe，总览能显示今天任务、补卡名额。
2. 任务页勾一项，等 1 秒，关掉重开，勾选还在。

## 10. 已知限制 / 下一步

- **任务页是 iframe**：为了保留每日/每周/每月和历史，直接嵌了旧页面，所以视觉和外壳不统一。以后可以重写成同一套 UI。
- **数据页只能看和补卡**：改文字、删任务、加任务还没有搬进来；需要的话再接入 `editor.html`。
- **补卡不能撤销**：按使用者要求。
- **补卡不标记**：完成率含补卡，报告也含。
- **补全工具会造空白日**：补出来的 0/5 会成为补卡对象，用之前先预览。
- **时间以本机为准**：改系统日期可以重置补卡名额，本地程序防不住。
- **依赖 Edge**：没有 Edge 会退回默认浏览器；Windows 11 自带。
- **app 安装包**：暂未做（使用者要求先不做）。

## 11. 故障排查

| 现象 | 先看 |
|---|---|
| 双击没反应 | `cyclequest.log`；确认 `%TEMP%` 可写 |
| 页面空白 | 端口是否被占用；日志里 `[服务]` 的端口 |
| 数据没保存 | `app_data.json` 是否只读；磁盘空间 |
| 报告 500 | `源码/report` 是否被打进 exe；`report.html` 是否可写 |
| 补卡按钮全灰 | 今天名额用完，或没有「最近未完成」的日期 |
| JSON 坏了 | 同目录会生成 `app_data.corrupt-时间.json`，从备份恢复 |

恢复数据：把 `app_data.backup-*.json` 里最近的一份改名成 `app_data.json` 即可。
改之前先关掉程序。

安卓工程结构：

```
CycleQuestMobile/
├─ app/src/main/java/com/cyclequest/mobile/MainActivity.java
├─ app/src/main/assets/index.html      ← 整个手机界面和逻辑
├─ app/src/main/AndroidManifest.xml
└─ app/build.gradle.kts
```

- `MainActivity` 只做四件事：加载 `index.html`、提供 `AndroidBridge` 读写 `state.json`、
  文件选择器（导入）、`ACTION_CREATE_DOCUMENT`（导出）。
- 界面是无网络的 WebView，**没有申请 INTERNET 权限**。
- 日期切换、勾选、历史、导入导出都在 `index.html` 里。

### 14.2 手机数据

手机本地只有一份：

```json
{
  "version": 1,
  "days": {
    "2026-11-24": {
      "tasks": [{"id":"d1","text":"...","meta":"","done":false,"void":false}],
      "importedAt": 1730000000000
    }
  },
  "lastImport": 1730000000000
}
```

存在 App 私有目录 `files/state.json`，卸载 App 会一起删除。
每天的 `tasks` 从最近一天复制，`done` 全部重置；所以日期会自动翻。

### 14.3 电脑导出格式

`GET /api/mobile/export-today`：

```json
{
  "app": "CycleQuestPC",
  "version": 1,
  "date": "2026-11-24",
  "tasks": [{"id":"d1","text":"...","meta":"","done":false}],
  "void_ids": []
}
```

手机导入时：

- 只认 `app == CycleQuestPC`。
- 任务列表以电脑为准，文字、meta 全部覆盖。
- `done` 取“电脑 true 或手机原本 true”，但 `void_ids` 里的强制 false。
- 导入的日期不是今天，就存成历史，并提示。

### 14.4 手机导出格式

`cyclequest-done-YYYY-MM-DD.json`：

```json
{"app":"CycleQuestMobile","version":1,"date":"2026-11-24","done_ids":["d1","d3"]}
```

电脑 `POST /api/mobile/import-done`：

- 只接受 `date == 今天`。
- 只把 `done_ids` 里、电脑当前为 false 的任务改成 true。
- 不改文字、不改历史、不改其他日期。
- 返回 `applied / already / skipped`，界面显示“新完成 N 项”。

### 14.6 已知限制

- 手动传文件，不会自动同步；忘了导出就会漏。
- 手机只能改今天；跨天未导出的完成不会自动上传。
- 补卡只在电脑上做，手机不参与名额计算。
- 电脑取消勾选不会自动同步到手机；要作废需在导出里加 `void_ids`（目前留空）。
- 手机端历史只显示本地导入过的日期，不是电脑全部历史。
- APK 没有图标资源，用系统默认图标；要换图标在 `res/mipmap` 加图并改 Manifest。
